# 기능요구사항_상세_API기준 — 모바일팀 작성·수정·제안 가이드

웹팀이 작성한 'API기준 상세' 시트는 우리 `openapi.yaml` 위에 쓰여 정합성이 높습니다.
모바일팀은 여기에 **① 플랫폼(앱) 계층의 처리 디테일을 보강**하고, **② 웹팀이 '보류'로 둔
항목 중 우리 API로 풀 수 있는 것을 채우고**, **③ 모바일 고유 요구사항을 신규 제안**합니다.

아래 표는 시트의 `항목 | 내용` 형식 그대로라 셀에 바로 붙여넣을 수 있습니다.

> **업데이트(2026-10-28)**: 금융인증서 로그인·간편비밀번호(6자리)·E2E 필드 암호화·보안 키패드는 앱에 구현 완료했고,
> API는 `openapi.yaml v1.2`에 `POST /auth/pin`, `POST /auth/login/pin`, `GET /crypto/e2e-key`, `EncryptedField`로 반영했습니다.

---
## 0. 작성 원칙 (모바일 행을 쓸 때)
- **담당 구분을 처리 앞에 표기**: `[앱]` 화면·단말 처리 / `[서버]` API 책임 / `[공통]`.
  같은 API라도 "앱이 무엇을 검증·암호화·저장하는가"를 서버 책임과 분리해 적는다.
- **단말 보안 처리를 반드시 명시**: 인증서/생체=Keystore 개인키 서명, 계좌·이체 비번=보안 키패드,
  중요화면=화면캡처 차단(FLAG_SECURE), 저장=암호화 저장소, 딥링크=접근통제.
- **오프라인·네트워크 예외**를 예외처리에 포함: 타임아웃·재시도(Idempotency-Key)·네트워크 끊김.
- **수용 기준은 측정 가능하게**: "3초 이내", "size≤100", "매 입력마다 키패드 배열 변경" 등.
- 플랫폼 정보는 `제약사항(CR)`과 연결: minSdk 26 / targetSdk 35 / Kotlin·Compose.

## 2. 보류 해제 제안 (우리 v1.1 API로 채움)
> 웹팀이 "API 미정의 보류"로 둔 FR-014·015 는 우리 `openapi.yaml v1.1` 에 이미 있음. 아래로 교체 제안.

### 표 10-14. FR-014 문의하기 (보류 → 작성)
| 항목 | 내용 |
| --- | --- |
| 요구사항 ID | FR-014 |
| 요구사항명 | 문의하기(1:1) |
| 정의 | 시스템은 사용자가 1:1 문의를 등록하고 답변 내역을 조회할 수 있게 해야 한다. |
| 선행 조건 | 사용자가 로그인 상태여야 한다. |
| 입력 | 제목, 내용 (※ 문의유형·첨부파일은 3-B 협의) |
| 처리 | [앱] ① `GET /inquiries` 로 내 문의 목록·답변상태 표시 ② 등록 시 `POST /inquiries`(헤더 `X-CSRF-Token`) ③ 제목·내용은 출력 시 escape |
| 출력 | 문의 목록(제목·상태 접수/답변완료), 등록 완료 메시지 |
| 예외 처리 | 403(CSRF 토큰 누락/불일치): 재시도 / 네트워크 오류: 재시도 안내 / 빈 입력: 등록 버튼 비활성화 |
| 수용 기준 | 상태변경 요청에 CSRF 토큰을 요구한다. 입력값은 HTML escape 되어 저장·표시된다(저장형 XSS 차단). |

## 3. 협의/신규 제안 항목
### 3-A. FR-001 로그인 문구 정정 (협의)
FR 목록은 'ID·비밀번호 및 인증서', 상세·API는 '인증서/생체'. **목록 문구를 '인증서/생체'로 정정**하거나
개발·비상용 ID/PW 로그인을 별도 FR로 추가할지 결정. (웹 정의서도 동일 지적 보유)

### 3-B. 문의 유형·첨부파일 (서버 협의)
현재 `POST /inquiries` 는 제목·내용만. 웹 보류안의 '유형·첨부파일'을 반영하려면
`type` 필드와 첨부 업로드(`POST /inquiries/{id}/attachments`, 확장자 화이트리스트·경로추적 방지)를 추가 정의 필요.

### 3-C. FAQ API 신규 (공통 제안)
`GET /faqs` (query: `category`, `q`, `cursor`, `size`) / 응답: `{id, category, question, answer}`. 비로그인 허용.

### 3-D. 모바일 고유 신규 요구사항 (앱 전용 — 추가 제안)
> 웹엔 없고 앱에만 필요한 항목. FR 또는 NFR(보안)로 등록 제안.

| 신규 ID(안) | 요구사항명 | 정의 | 관련 API |
| --- | --- | --- | --- |
| FR-025 | 기기·세션 관리 | 사용자가 바인딩된 기기 목록·활성 세션을 조회하고 특정 기기/세션을 해제·종료할 수 있게 한다. 기기 변경 시 기존 토큰 무효화. | GET/POST /devices, DELETE /devices/{id}, GET /sessions, DELETE /sessions/{id} |
| FR-026 | 앱 실행 보안 | 앱 실행 시 루팅·디버깅·에뮬레이터 등 위험 신호를 평가해 안내하고, 중요화면 캡처·백그라운드 노출을 차단한다(FLAG_SECURE). | GET /security/status (+ 단말 로컬 점검) |

## 4. 요약
- **수정**: FR-001/002/005/006/018 에 단말 보안 처리(Keystore·보안키패드·FLAG_SECURE·자동로그아웃·페이지네이션)를 `[앱]`으로 추가.
- **보류 해제**: FR-014·015 는 우리 v1.1 API(`/inquiries`,`/notices`)로 바로 작성 가능.
- **신규/협의**: FAQ(`/faqs`) 신규, 기기·세션관리(FR-025)·앱실행보안(FR-026) 추가, 문의 첨부·알림 수신방법·주소 필드는 서버 협의.
